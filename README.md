# LOXX — Digital Product Studio

وب‌سایت فارسی استودیو LOXX بر اساس کانسپت نئونی و لوگوی دقیق ارسالی: لندینگ، شش صفحه خدمات، چهار نمونه‌کار با جزئیات، برآورد زنده پنج نوع پروژه، مسیر آشنایی چهارمرحله‌ای، نه مقاله کامل، فرم درخواست متصل به API و پنل مدیریت.

انتخاب‌ها، هدف و بودجه از بریف سه‌مرحله‌ای به فرم منتقل می‌شوند. فرم به API و دیتابیس متصل است. بلاگ و sitemap از مقاله‌های منتشرشده مدیریت می‌خوانند. شماره تماس: `09375302400`.

### مدیریت و محتوای زنده

پس از اجرای محلی با مشخصات خصوصی `LOCAL_LOGIN.txt` در `/login` وارد شوید و `/admin` را باز کنید. مدیر می‌تواند مقاله بسازد، متن Markdown و عنوان/توضیح سئو را ویرایش کند، پیش‌نویس را منتشر کند، وضعیت درخواست‌ها را تغییر دهد و درخواست‌ها را جست‌وجو یا فیلتر کند. صفحه مدیریت از کاربران عادی محافظت شده است. ثبت پیش‌درخواست، پرداخت یا رزرو خودکار ایجاد نمی‌کند.

محتوای اولیه در `content/articles.json` قرار دارد. seed محتوای ویرایش‌شده مدیریت را بازنویسی نمی‌کند. قیمت‌ها در `apps/web/lib/pricing.ts` بودجه‌های پیشنهادی اولیه‌اند؛ مبلغ نهایی به محدوده توافق‌شده وابسته است.

بریف کامل درخواست برآورد با حفظ خط‌های متن و جدا از امکانات منتخب ذخیره می‌شود و در مدیریت و حساب کاربر قابل مشاهده است. پیش‌نمایش مقاله با نمایشگر Markdown بلاگ یکسان است؛ ویرایش‌های ذخیره‌نشده مشخص می‌شوند و تعویض مقاله یا ترک صفحه هشدار دارد. شماره‌های فارسی در سرور هم یکسان‌سازی می‌شوند و شماره نامعتبر پذیرفته نمی‌شود.

### اجرا در ویندوز

1. Node.js نسخه 22.12 یا جدیدتر و Git نصب باشند؛ دسترسی به GitHub برای بررسی آخرین نسخه لازم است.
2. فایل‌های مخزن یا ZIP را در `D:\loxx\website` قرار دهید.
3. پنجره اجرای قبلی سایت را ببندید و فایل `START-LOXX.bat` را اجرا کنید. آخرین نسخه `origin/main` دریافت و تطبیق داده می‌شود؛ سپس وابستگی‌ها و دیتابیس محلی آماده و نسخه production ساخته و اجرا می‌شود.
4. سایت در `http://localhost:3000` و API در `http://localhost:4100/api/health` اجرا می‌شود.

اگر فقط لانچر را دانلود کرده‌اید، مخزن را در `D:\loxx\website` دریافت می‌کند. اگر لانچر کنار `package.json` باشد، همان پوشه پروژه انتخاب می‌شود. برای تعیین مسیر دیگر، متغیر محیطی `LOXX_PROJECT_DIR` را تنظیم کنید.

لانچر برای نصب‌های ZIP هم کار می‌کند: ابتدا از سورس و داده‌های محلی در پوشه هم‌سطح `.loxx-launcher-website/backups` پشتیبان می‌گیرد و سپس Git را راه می‌اندازد. در مخزن موجود، تغییرات ثبت‌نشده با `git stash` و کامیت‌های قبلی با شاخه‌های `loxx-backup-*` نگهداری می‌شوند. تغییرات محلی خودکار روی نسخه جدید اعمال نمی‌شوند؛ برای بازیابی، `git stash list` و `git stash apply` یا شاخه پشتیبان را بررسی کنید.

شناسه کامیت محلی و `origin/main` باید در خروجی با `[MATCH]` یکسان باشند. اگر دریافت نسخه جدید شکست بخورد، سورس ناسازگار باشد یا پورت‌های 3000 و 4100 اشغال باشند، اجرا متوقف می‌شود. لاگ و مشخصات نسخه در پوشه هم‌سطح `.loxx-launcher-website` قرار می‌گیرند. نصب وابستگی‌ها از `package-lock.json` با `npm ci` انجام می‌شود و در صورت تغییر ورودی‌ها تکرار خواهد شد. کش تولیدشده Next.js قبل از اجرا پاک می‌شود؛ مرورگر پس از پاسخ‌دادن سایت و API باز می‌شود.

مشخصات ورود مدیر محلی در فایل خصوصی `LOCAL_LOGIN.txt` ساخته می‌شود. این فایل، دیتابیس و فایل‌های محیطی وارد Git نمی‌شوند. برای توقف سرورها `Ctrl+C` بزنید.

### توسعه

```bash
npm ci
npm run setup:local
npm run dev
```

```bash
npm test
npm run typecheck
npm run build
npm start
```

ساختار: `apps/web` رابط Next.js، `apps/api` سرویس NestJS و Prisma با SQLite محلی، `tools/setup-local.mjs` راه‌اندازی دیتابیس و رمز تصادفی مدیر. API از طریق مسیر هم‌مبدأ `/api` پروکسی می‌شود. برای اجرای عمومی، دامنه واقعی را در `WEB_ORIGIN` و `NEXT_PUBLIC_SITE_URL` تنظیم کنید و یک `SESSION_SECRET` تصادفی اختصاصی داشته باشید.

لوگو و آیکن از فایل اصلی ارسالی استخراج شده‌اند. نمونه‌کارهای GoldenCheat، پلتفرم آن و Ahmadi Design با اتکا به معرفی صاحب پروژه آمده‌اند؛ نسخه جدید مهراد کویر با تصویر ارسالی و برچسب «در انتظار انتشار» معرفی می‌شود. نام و عکس شخصیت‌های بخش تیم، مفهومی و به‌وضوح برچسب‌خورده‌اند؛ اعضای واقعی معرفی نشده‌اند. آمار یا رضایت‌نامه ساختگی وجود ندارد. تصاویر WebP بهینه‌اند و فونت Vazirmatn محلی است. مشخصات تصاویر در [visual-assets.md](docs/visual-assets.md) و [team-image-prompts.md](docs/team-image-prompts.md) آمده است.

راهبرد کلمات کلیدی و محتوا: [seo-keyword-strategy.md](docs/seo-keyword-strategy.md). انتشار VPS، تنظیم دامنه، فعال‌کردن ایندکس و Search Console: [production-checklist.md](docs/production-checklist.md). نسخه‌های محلی و پیش‌نمایش noindex هستند؛ production نیازمند `NEXT_PUBLIC_SITE_URL` واقعی است. رتبه یا زمان رسیدن به صفحه اول تضمین نشده است.

پیش از build روی میزبان عمومی، تنظیمات نمونه `apps/api/.env.production.example` و `apps/web/.env.production.example` را با مقادیر واقعی تنظیم و `npm run check:production` را اجرا کنید. این بررسی رمزها را چاپ نمی‌کند و جایگزین انتشار واقعی، HTTPS و پشتیبان‌گیری نیست. آزمون یکپارچه نسخه تولید پس از build: `node tools/smoke-studio.mjs`؛ روی دیتابیس موقت اجرا می‌شود و انتشار/عدم انتشار مقاله را در بلاگ و sitemap واقعی، بدون build مجدد، بررسی می‌کند.

این پروژه برای اجرا به وب‌سرور نیاز دارد؛ فایل TSX با دوبارکلیک در مرورگر اجرا نمی‌شود. میزبانی عمومی در این تغییر فعال نشده است.
