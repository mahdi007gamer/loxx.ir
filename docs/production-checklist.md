# انتشار LOXX روی دامنه اصلی

سورس برای اجرای وب Next.js و API NestJS روی Node.js 22.12 یا جدیدتر آماده شده است. تغییر سورس در GitHub، به‌خودی‌خود انتشار روی VPS یا دامنه نیست. تنظیم DNS، گواهی HTTPS و سرویس اجرای دائمی باید روی میزبان انجام شود.

## اجرای نسخه جدید

در ویندوز، `START-LOXX.bat` آخرین `main` را بررسی و اجرا می‌کند. برای اجرای دستی:

```bash
npm ci
npm run setup:local
npm run build
npm start
```

`API_PORT` پیش‌فرض 4100 و `WEB_PORT` پیش‌فرض 3000 است. اگر میزبان `PORT` بدهد، فقط وب از آن استفاده می‌کند؛ پورت API جدا می‌ماند. API را فقط از شبکه داخلی یا پشت پراکسی قابل دسترسی نگه دارید.

## تنظیمات انتشار

فایل `apps/web/.env.production.example` را به `apps/web/.env.production` کپی کنید. `NEXT_PUBLIC_SITE_URL` باید URL واقعی دامنه باشد و پیش از build تنظیم شود. برای فعال‌کردن ایندکس، `NEXT_PUBLIC_ALLOW_INDEXING=true` بگذارید. تا زمانی که دامنه واقعی در محیط production صراحتاً تنظیم نشده، سایت و robots برای پیش‌نمایش noindex می‌مانند.

نمونه تنظیمات API در `apps/api/.env.production.example` است. آن را روی میزبان در `apps/api/.env` قرار دهید و مقادیر نمونه را عوض کنید. `WEB_ORIGIN=https://loxx.ir,https://www.loxx.ir` بدون اسلش پایانی و `NODE_ENV=production` برای کوکی HTTPS لازم‌اند. `SESSION_SECRET` باید تصادفی، اختصاصی و حداقل ۳۲ کاراکتری باشد. API در production با رمز امضای نمونه، Origin ناامن یا دیتابیس حافظه‌ای شروع نمی‌شود. `ADMIN_EMAIL` واقعی و `ADMIN_PASSWORD` تصادفی حداقل ۱۶ کاراکتری برای آماده‌سازی اولیه مدیر تنظیم کنید؛ رمز محلی را عمومی نکنید. اتصال وب به API از `API_URL=http://127.0.0.1:4100` استفاده می‌کند.

برای ساخت مقدار تصادفی، دستور زیر را جداگانه برای رمز مدیر و کلید امضای نشست روی میزبان اجرا و خروجی‌ها را فقط در تنظیمات خصوصی همان میزبان نگه دارید:

```bash
node -e "process.stdout.write(require('node:crypto').randomBytes(48).toString('base64url'))"
```

پس از تنظیم فایل‌های محیطی و نصب وابستگی‌ها، پیش از build اجرا کنید:

```bash
npm run check:production
```

این فرمان هم‌خوانی دامنه canonical با Origin فرم، انتخاب صریح ایندکس، تنظیمات کوکی، کلید امضا، مشخصات اولیه مدیر، URL داخلی API و مسیر مطلق SQLite را بررسی می‌کند. مقدار رمزها و مسیر خصوصی دیتابیس را چاپ نمی‌کند. موفقیت آن فقط صحت تنظیمات است؛ انتشار، DNS، گواهی TLS یا وجود پشتیبان را تأیید نمی‌کند. هنگام تغییر `NEXT_PUBLIC_*` یا `API_URL` دوباره build بگیرید؛ این مقادیر هنگام ساخت نسخه وب استفاده می‌شوند.

داده SQLite و فایل‌های محیطی را خارج از انتشار سورس نگه دارید و از دیتابیس پشتیبان زمان‌بندی‌شده تهیه کنید. `setup:local` محتوای تحریریه و مدیر اولیه را به‌صورت idempotent آماده می‌کند؛ تغییرات بعدی مدیریت نباید با اجرای seed بازنویسی شوند.

برای دیتابیس production، نمونه مسیر `file:/var/lib/loxx/studio.db` است. پوشه را با دسترسی نوشتن برای کاربر سرویس بسازید. قبل از هر به‌روزرسانی ساختار، پشتیبان سازگار SQLite تهیه و بازیابی آن را بررسی کنید. `db:push` را با گزینه‌های پذیرش حذف داده یا reset اجرا نکنید. seed رمز مدیر موجود را عوض نمی‌کند؛ عوض‌کردن `ADMIN_PASSWORD` در فایل محیطی، رمز حساب قبلی را تغییر نمی‌دهد.

## مسیر مدیریت و محتوا

- ورود: `/login`؛ مشخصات مدیر محلی در `LOCAL_LOGIN.txt` است.
- مدیریت: `/admin`؛ فقط نشست کاربر با نقش مدیر اجازه دریافت اطلاعات دارد.
- مقاله‌ها: ایجاد، ذخیره پیش‌نویس، انتشار، ویرایش متن Markdown و فیلدهای سئو.
- درخواست‌ها: مشاهده مشاوره‌ها و برآوردها، جست‌وجو و تغییر وضعیت.
- متن کامل بریف و امکانات منتخب جدا ذخیره می‌شوند؛ درخواست‌های نسخه‌های قبلی هم قابل مشاهده‌اند.
- پیش‌نمایش مدیریت از همان نمایشگر امن Markdown بلاگ استفاده می‌کند؛ تغییرات ذخیره‌نشده مشخص می‌شوند و تعویض مقاله یا ترک صفحه هشدار دارد.
- بلاگ از API می‌خواند؛ حذف انتشار مقاله باید آن را از فهرست عمومی خارج کند.

پس از انتشار، صفحه اصلی، یک مقاله، یک صفحه خدمت، یک نمونه‌کار، ثبت فرم و ورود مدیریت را روی HTTPS بررسی کنید. سپس sitemap را در Google Search Console ثبت کنید. راهبرد محتوا و محدودیت‌های رتبه‌گیری در `seo-keyword-strategy.md` آمده است.

آزمون خودکار پس از build با `node tools/smoke-studio.mjs`، دیتابیس و حساب مدیر موقت می‌سازد و ثبت درخواست، ذخیره بریف، انتشار/برداشتن از انتشار مقاله و تغییر فوری بلاگ و sitemap را بدون build دوباره بررسی می‌کند. این آزمون از پورت API شماره ۴۱۰۰ استفاده می‌کند؛ ابتدا اجرای عادی محلی را متوقف کنید. داده‌های اصلی سایت تغییر نمی‌کنند.

راهنمای رسمی میزبانی Next.js: https://nextjs.org/docs/app/guides/self-hosting ؛ پراکسی معکوس HTTPS را مقابل سرور وب قرار دهید و پورت API را عمومی نکنید.

## مواردی که باید قبل از انتشار تأیید شوند

بازه‌های قیمت، بودجه‌های پیشنهادی اولیه‌اند؛ بازبینی تجاری لازم دارند. پروژه مهراد کویر با وضعیت انتظار انتشار معرفی شده است. بخش تیم از شخصیت‌های تصویرسازی‌شده با برچسب کوتاه استفاده می‌کند؛ برای معرفی اعضای واقعی، اطلاعات و تصاویر مجاز را جایگزین کنید. ادعاهای بدون سند، نظرات ساختگی، شمارنده مشتری یا تضمین رتبه در سایت وجود ندارد.
