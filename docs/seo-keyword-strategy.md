# راهبرد جست‌وجو و تبدیل LOXX

تاریخ بررسی: ۷ آبان ۱۴۰۵ / 2026-10-29

این سند نقشه اجرایی شروع است، نه ادعای فهرست تمام عبارت‌های ممکن. عبارت‌ها از خدمات واقعی LOXX، پرسش‌های تصمیم خرید و مرور نتایج جست‌وجوی فارسی انتخاب شده‌اند. دسترسی به داده تأییدشده Keyword Planner یا Search Console این دامنه در این بررسی وجود نداشت؛ بنابراین حجم جست‌وجو، سختی، رتبه فعلی، ترافیک و زمان رسیدن به رتبه برای هیچ عبارت ساخته نشده است. اولویت‌های زیر فرضیه اجرایی‌اند و پس از انتشار باید با داده واقعی اصلاح شوند.

## جایگاه و پیام

LOXX برند تازه تیمی باتجربه در طراحی و ساخت محصولات دیجیتال است. حقوق انتشار تجربه‌های پیش از این برند رعایت می‌شود. نمونه‌کار مجاز، توضیح مسئله و راه‌حل، محدوده مکتوب، راه تماس مستقیم و تحویل مرحله‌ای باید جای ادعاهای کلی یا آمار ساختگی را بگیرند. تصویر مفهومی تیم نباید در داده ساختاریافته به‌عنوان اشخاص واقعی معرفی شود.

هدف تبدیل: بازدیدکننده بتواند خدمت مناسب را تشخیص دهد، بازه بودجه و خروجی را بفهمد، بریف اولیه ثبت کند و برای پیشنهاد دقیق با تیم گفت‌وگو کند. ثبت درخواست به‌معنای خرید، پرداخت یا رزرو نیست.

این جدول بیش از ۱۴۰ ترکیب و موضوع نزدیک را پوشش می‌دهد، اما به‌معنای نیاز به ۱۴۰ صفحه نیست. خوشه‌ها برای انتخاب عنوان، پوشش پرسش‌های واقعی و لینک‌سازی داخلی‌اند. نام شهرها فقط زمانی هدف‌گذاری شود که خدمت یا محتوای محلی مستند و متفاوت وجود داشته باشد؛ ساخت صفحات مشابه برای هر شهر پیشنهاد نمی‌شود.

## مرزبندی نیت برای جلوگیری از رقابت داخلی

- صفحه خدمت به «چه می‌سازیم، برای چه کسی، محدوده و مسیر سفارش» پاسخ می‌دهد.
- مقاله هزینه به «چرا قیمت فرق دارد و چگونه پیشنهادها را مقایسه کنیم» پاسخ می‌دهد و به خدمت مرتبط لینک می‌دهد.
- مقاله بریف یک چک‌لیست اجرایی دارد؛ متن صفحه خدمت را تکرار نمی‌کند.
- مطالعه موردی درباره همان پروژه است؛ آمار نتیجه، رتبه، مشتری یا درآمد بدون داده تأییدشده به آن اضافه نمی‌شود.
- دسته و جست‌وجوی وبلاگ برای پیدا کردن مقاله‌اند؛ هر ترکیب فیلتر نباید URL ایندکس‌پذیر مستقل تولید کند.

## مسیر تبدیل پیشنهادی

۱. عبارت تصمیم‌محور ← مقاله کاربردی با جواب روشن و مثال
۲. مقاله ← صفحه خدمت دقیق با محدوده، بازه اولیه و نمونه مرتبط
۳. صفحه خدمت ← فرم با انتخاب نوع خدمت از پیش تنظیم‌شده
۴. فرم ← ثبت واقعی درخواست و پیام موفق قابل تشخیص
۵. پنل مدیریت ← تعیین وضعیت پیگیری و گفت‌وگو برای پیش‌فاکتور

در مقاله‌ها، دعوت به اقدام پس از بخش تصمیم و در پایان قرار می‌گیرد. دعوت باید با موضوع مرتبط باشد: برای CRM «فرایند فروش فعلی را بنویسید»، برای سایت شرکتی «فهرست خدمات و هدف تماس را بفرستید». تکرار پنجره یا پیشنهاد اجباری در میان مطالعه، جای محتوای مفید را نمی‌گیرد.

## فنی پیاده‌شده

- URL مستقل و HTML قابل دریافت برای شش خدمت و مقاله‌ها؛ مسیرهای ناشناخته 404 می‌شوند.
- عنوان و توضیح مستقل، canonical مطلق، پیش‌نمایش اشتراک، زبان فارسی و جهت راست‌به‌چپ.
- داده ساختاریافته Organization و WebSite با شماره واقعی، Service و Breadcrumb برای خدمات؛ Article برای محتوای وبلاگ. امتیاز، نظر مشتری یا اعضای ساختگی به schema اضافه نمی‌شود.
- `sitemap.xml` با مسیرهای اصلی، خدمات، نمونه‌کار، سیاست‌ها و مقاله‌های منتشرشده زنده. مقاله پیش‌نویس یا حذف‌شده از API سالم وارد sitemap نمی‌شود؛ fallback فقط برای خطای دسترسی API است.
- `robots.txt` محیط انتشار و محیط محلی جداست. پنل و API محل انتشار محتوای جست‌وجویی نیستند؛ داده مدیریتی علاوه بر کنترل ایندکس با احراز هویت محافظت می‌شود.
- فایل تصویر سبک، ابعاد مشخص تصویر و بارگذاری تنبل بخش‌های پایین صفحه در ساختار پروژه استفاده می‌شود. امتیاز یا اندازه‌گیری واقعی عملکرد باید بعد از استقرار گزارش شود، نه حدس زده شود.

`meta keywords` عامل رتبه‌بندی گوگل نیست؛ فیلد keywords مدیریت برای برنامه‌ریزی موضوع و ویرایشگر است. داده ساختاریافته هم تضمین نمایش نتیجه ویژه یا رتبه نیست.

## انتشار روی دامنه اصلی

۱. متغیرهای محیط تولید را تنظیم کنید: `NODE_ENV=production`، `NEXT_PUBLIC_SITE_URL=https://loxx.ir` و `NEXT_PUBLIC_ALLOW_INDEXING=true`. آدرس عمومی باید هنگام ساخت فرانت‌اند در دسترس باشد. `API_URL` سمت سرور و `WEB_ORIGIN` API نیز با استقرار هماهنگ باشند.
۲. تا قبل از آماده بودن، `NEXT_PUBLIC_ALLOW_INDEXING=false` بماند. پیش‌نمایش عمومی بهتر است با احراز هویت محدود شود. نبودن URL صریح عمومی، محیط توسعه و میزبان محلی در این پیاده‌سازی noindex هستند.
۳. HTTPS، نسخه اصلی دامنه و ریدایرکت یک‌مرحله‌ای `www`/بدون `www` را در میزبانی یکسان کنید. canonical و sitemap باید همان نسخه انتخاب‌شده را نشان دهند.
۴. روی دامنه واقعی صفحه اصلی، شش خدمت، یک مقاله و یک مطالعه موردی را با موبایل و ابزار URL Inspection بررسی کنید. نبود noindex ناخواسته، وضعیت 200، دسترسی CSS/JS و محتوای متن را کنترل کنید.
۵. مالکیت دامنه را در Google Search Console با دسترسی مجاز تأیید و `https://loxx.ir/sitemap.xml` را ثبت کنید. تأیید دامنه و ارسال sitemap در این کار بدون دسترسی مالکیت انجام نشده است.
۶. لینک‌های داخلی و خطاهای 404 را بررسی کنید. اگر دامنه قبلاً سایت داشته، فهرست URLهای قبلی و ریدایرکت‌های لازم را پیش از جایگزینی تهیه کنید.
۷. ثبت فرم، احراز هویت مدیر، حریم خصوصی و امکان پشتیبان‌گیری را در محیط واقعی آزمون کنید؛ سئو بدون مسیر دریافت و پاسخ‌گویی به درخواست، هدف کسب‌وکار را کامل نمی‌کند.

نکته robots: `Disallow` به‌تنهایی روش قطعی حذف URL از نتایج نیست. برای اینکه Google یک noindex را ببیند، باید امکان دریافت آن صفحه را داشته باشد. پنل خصوصی باید با احراز هویت محافظت شود؛ روی noindex یا robots برای امنیت حساب تکیه نکنید. اگر صفحه عمومی قبلاً ایندکس شده است، شیوه حذف یا noindex قابل خزش را متناسب با وضعیت انتخاب کنید.

برای سنجش، تاریخ و موضوع تغییر ثبت شود. قیاس نرخ تبدیل به تعریف رویداد و داده کافی نیاز دارد. پر کردن سایت با مقاله‌های مشابه، خرید لینک یا تغییر تاریخ بدون به‌روزرسانی واقعی بخشی از این برنامه نیست. اولویت با صفحه‌ای است که مسئله مشتری را کامل‌تر حل می‌کند.

## منابع و محدودیت شواهد

منابع فنی اصلی، بازبینی‌شده در تاریخ این سند:

- [Google SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide): ساختار قابل فهم، لینک‌های قابل خزش، عنوان و محتوای مفید؛ رتبه اول یا ایندکس تضمین‌شده نیست.
- [Google — Helpful, reliable, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content): ارزش مستقل، شفافیت تخصص و پرهیز از محتوای ساخته‌شده صرفاً برای جست‌وجو.
